Problem Statement No. 25

📡 AI-Powered Signal Quality Analyzer

An intelligent telecom monitoring system that analyzes SNR, BER & latency — detects degradation, explains root causes, and predicts failures using IBM Granite via watsonx.ai.

Problem Statement

Challenge: Reliable telecom systems depend on signal quality metrics — Signal-to-Noise Ratio (SNR), Bit Error Rate (BER), and latency. Engineers need an intelligent system that analyzes measurement data, detects degradation, explains root causes, and predicts failures before they impact service.

Solution Architecture

1
Data Ingestion CSV/JSON upload or synthetic generator → schema validation, missing-value imputation, outlier clipping, rolling stats (mean, std, EWMA, trend) per node
2
Detection Engine 4-layer detection: rule-based thresholds + rolling z-score + Isolation Forest + degradation/interference pattern analysis → severity scoring (Normal → Low → Medium → High → Critical)
3
Forecasting Engine Per-node Prophet → ARIMA → GBM cascade for SNR, BER & latency → failure probability (0–1), time-to-failure (hours), risk ranking
4
IBM Granite Insights Structured context sent to watsonx.ai → root cause, confidence score, affected nodes, prioritized recommendations + plain-language engineer summary. Deterministic mock fallback when offline.
5
FastAPI + Streamlit REST layer (5 endpoints) consumed by a 6-tab Streamlit dashboard with upload panel, time-series charts, anomaly table, node heatmap, forecast charts, and AI insights panel

Technology Stack

IBM Granite (granite-13b-instruct-v2) watsonx.ai API IBM Cloud Code Engine Python 3.11/3.12 FastAPI Streamlit pandas · numpy scikit-learn Prophet statsmodels (ARIMA) Plotly Docker pytest (67 tests)

Core Features

📥 Signal Data Processing
  • CSV / JSON upload with schema validation
  • Column aliases (snr_db, latency_ms)
  • Per-node ffill/bfill + median imputation
  • Physical range clipping
  • Rolling mean, std, EWMA (windows 5/15/30)
  • Linear trend coefficient per node
  • Synthetic generator: 5 scenarios
⚠️ Anomaly & Degradation Detection
  • Rule-based: SNR < 10 dB, BER > 1e-3, latency > 150 ms
  • Rolling z-score per node (window=30)
  • Isolation Forest (contamination=5%)
  • Severity: Normal / Low / Medium / High / Critical
  • Correlated SNR↓ + BER↑ interference detection
  • Periodic burst detection (autocorrelation)
  • Sustained trend degradation flagging
🤖 IBM Granite AI Insights
  • Context-aware prompt to Granite-13b-instruct
  • Returns: root cause, confidence (0–1)
  • Affected nodes + time window
  • Prioritized, actionable recommendations
  • Plain-language engineer summary
  • Structured JSON response schema
  • Full offline mock fallback (no credentials needed)
🔮 Failure Prediction
  • Prophet → ARIMA → GBM cascade per metric
  • Log-transform on BER (6 orders of magnitude)
  • 95% confidence bands on forecasts
  • Failure probability: logistic from breach fraction
  • Time-to-failure (hours until first breach)
  • Risk ranking: Low / Medium / High / Critical
  • MAE + RMSE on 20% holdout

Severity Scoring Model

Each row accumulates a score from all triggered flags. Extreme values add bonus points.

ScoreLabelTriggered by
0NormalNo flags
1Low1 flag (e.g. z-score OR rule breach)
2Medium2 flags
3–4High3–4 flags or moderately extreme values
≥ 5Critical5+ flags or SNR < 5 dB / BER > 1e-2 / latency > 300 ms

Key Design Decisions

DecisionRationale
Prophet → ARIMA → GBM cascadeGraceful degradation: Prophet handles seasonality best; ARIMA is faster; GBM with lag features is always available as a reliable fallback
Log-transform on BERBER spans 6+ orders of magnitude — log-scale makes it approximately Gaussian, improving fit for all statistical models
Hybrid detection (rules + ML)Rule-based flags catch known operational thresholds reliably; Isolation Forest catches novel multi-dimensional patterns that rules miss
Deterministic mock for GraniteEnables full offline operation and demos without credentials; mock is context-aware and returns the identical JSON schema as the real API
In-memory AppState in APIAppropriate for prototype/demo; designed to be swapped for Redis or a database for multi-user production deployments
Modules called directly from StreamlitNo HTTP round-trip needed for the dashboard — faster, simpler, single-process for local use

Push to IBM Container Registry — ibmcloud cr push us.icr.io/signal-analyzer-ns/signal-analyzer:latest

Deploy to Code Engine — ibmcloud ce application create with env vars for WATSONX_API_KEY, WATSONX_PROJECT_ID. Min scale = 1.
4
Optional: Cloud Object Storage — bind COS bucket for persistent dataset uploads instead of in-memory state
